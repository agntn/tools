## Decisions and evidence

- **Author schemas with `Type` from `@agntn/tools`, never `import { Type } from "typebox"`.** OMP's loader rewrites the bare `typebox` specifier across the extension graph to its omptype facade (`extensibility/plugins/legacy-pi-compat.ts`, `TYPEBOX_SPECIFIER_FILTER`), whose schemas are functions. `Value.Check` from the unremapped `typebox/value` then accepts any value, so validation silently vanished in the first probe. `defineTool` throws on a callable schema.
- **`@agntn/*` skips the release cooldown** (#9): pnpm 11 holds back any version under a day old, and a clean install (CI, Workers Builds, a fresh store) refused `@agntn/web@0.7.5` 11 hours after its release, while a warm local cache let it through. These are our own packages, so the scope pattern covers the next sibling and the next bump; the `@oh-my-pi` and Vite+ entries stay pinned to one version.
- **TypeBox is bundled into `dist`** (devDependency, one 265 KB chunk). Unbundled, its 688 modules each pass the OMP loader: +200 ms per OMP start (median 1.196 s vs 0.996 s); bundled +20 ms. A bundled copy also has no bare `typebox` import left to remap.
- **The bundled TypeBox declarations go through a patched rolldown-plugin-dts** (`patches/rolldown-plugin-dts@0.28.6.patch`, #11). 0.28.6 broke three TypeBox shapes in `typebox.d.mts`, so a consumer without `skipLibCheck` got 32 errors: a type parameter named like a namespace import (`Result extends Result.TResult`, upstream sxzz/rolldown-plugin-dts#307, fix taken from #308), an `infer` name used deeper than the conditional's direct child (`[Optional, Rest]` bound to TypeBox's `Optional()`), and a global type named like a function of the module (`Record<PropertyKey, unknown>` beside TypeBox's `Record()`). The JS output is byte-identical with and without the patch. `pnpm typecheck:dist` checks `index`, `cli` and `mcp` declarations without `skipLibCheck` after the build, in CI, Publish and `release`; `ai`, `h3`, `pi` and `omp` stay out because their hosts' own declarations fail it (`@ai-sdk/provider` imports untyped `json-schema`, h3 imports its optional peer `crossws`, Pi and OMP internals). A new rolldown-plugin-dts stops `pnpm install` on `ERR_PNPM_UNUSED_PATCH`: check whether upstream fixed all three before moving or dropping the patch.
- **OMP gets the schema through `pi.typebox.Type.Unsafe(json)`.** The host build validates the raw JSON Schema with its full validator and emits it verbatim; standalone omptype `Unsafe` validates nothing, so the OMP test double emulates the host with TypeBox.
- **Schema types come from `@agntn/tools` too** (`export type * from "typebox"`): with TypeBox bundled, a consumer that exports a definition can name every type its schema uses only through this package, and its own `typebox` types would be a second, mismatched copy.
- **Executors load lazily in the consumer:** `execute: async (p) => (await loadOperations()).op(p)` with a cached dynamic import, so the extensions register tools without loading the library (hashes: only the contract and `@agntn/tools` are static imports of `dist/tools.mjs`).
- **Validation errors are one failure per line** (format taken from agntn/hashes): an unknown key names itself with the keys its object takes, at any depth, and an enum failure lists the allowed values. Nested keys come from TypeBox's `schema is false` against a closed object's `additionalProperties`, with the object's path in front (#19). Each branch of a union fails on its own, so a key some branch takes gets no line and a key none takes lists every branch (`takes {kind, radius} or {kind, side}`); root keys are read off the arguments, since TypeBox stops at 8 errors and a tenth extra key would drop out. `ToolInputError.lines` carries them, and MCP `errorResult` sanitizes each line alone, so a newline inside an executor or provider message still becomes a space.
- **AI SDK output is `{ ...details, text }`** and a failure throws (hashes' contract); `toAiTool` keeps input and details types, but a consumer annotates exported tools itself.
- **Test double for `pi.typebox`:** standalone omptype `Type.Unsafe` returns one shared schema object for every call, so the double wraps each document in its own callable; patching the shared one made every tool validate with the last schema registered.
- **The core validates on every surface** (`invokeTool`), because a host may skip validation and OMP's omptype drops `pattern`.
- **Hosts' own result renderers pass through** (`renderers[name].renderResult` for Pi and OMP): books keeps its bounded preview of long output. The OMP status line (`describeCall`, `describeResult`) stays the adapter's.
- **AI SDK details must not have a `text` field**: `{ ...details, text }` would overwrite one of them, so the adapter throws. books renamed its slice to `slice`.
- **OMP renderers get the host `Text` injected** by the extension; the adapter imports only types from `@oh-my-pi/pi-coding-agent`.
- **Pi failures throw by default** (`failures: "throw"`): Pi up to 0.98 treats a returned `isError` as success. `"return"` needs a peer range of `>=0.99.0`.
- **MCP sends the title twice**, top level and `annotations.title` (#21): Claude Code 2.1.289 names a tool by `annotations?.title || name` and never reads the top-level one, so without it every tool showed up by its wire name.
- **MCP uses SDK v2's low-level `Server`, not `McpServer`.** `McpServer.registerTool` in 2.2.0 takes any Standard Schema with JSON Schema, so TypeBox would fit, but a probe showed it answers `toString`, `constructor` and `__proto__` with "Tool toString disabled" (a lookup that reaches `Object.prototype`), echoes a raw tool name with a newline and ESC into its JSON-RPC error, joins validation failures into one line and passes a thrown message with its newline unsanitized. `Server` is `@deprecated` in v2 as in v1. v2 over v1 anyway: 2 runtime dependencies (`zod`, `@modelcontextprotocol/core`) instead of 17 (express, hono, cors, ajv, jose and more). The handler's abort signal is `ctx.mcpReq.signal`; stdio is `@modelcontextprotocol/server/stdio`, the test client `@modelcontextprotocol/client`.
- **One parse: `parseWords`, on `util.parseArgs` with tokens.** A scanner beside citty's parse drifted from it four times in review (#17): citty runs `util.parseArgs` with `strict: false` after dropping every `--no-*` word, so an undeclared `--x` shifted its value into the positionals, a repeated option kept the last, `-times 2` became five short flags while `2` was skipped, and `--read_only` and `--no-cache v` set nothing. Only `--flag`, `--flag=value` and `--no-flag` for a boolean are options; camelCase and snake_case spellings are unknown options. `--help` and `-h` count only as option tokens, so after `--` or as an option's value they are the tool's words. Values: integers and booleans by `Value.Convert` against the tool schema, objects and arrays as JSON, then `invokeTool` validates as on every surface; parsed values and the input are null-prototype records, so `toString` is a plain property.
- **Dispatch and usage are the adapter's own** (`dispatch`, `mainUsage`, `commandUsage`): the first word is `--version`, `--help`, a command or an alias; an empty line prints the usage on stderr with exit 1. citty's `runMain` took `--help` anywhere on the line and echoed the raw command word into its errors, so a newline in a word forged a line; here every error line goes through `sanitizeLine`, with the unknown word in `JSON.stringify`. The CLI writes no colors, so it has nothing to decide about the terminal. Command names, derived or hinted, and aliases must match `/^[a-z0-9_][a-z0-9_.:-]*$/i`; an option-like or empty one could never be dispatched. Option flags must match `/^[a-z0-9][a-z0-9.-]*$/` (positionals are never options, so their keys need no flag spelling) (a property named `""` or `a=b` has no `--flag` to spell it), a boolean flag cannot start with `no-` (`util.parseArgs` reads `--no-cache` as `cache` negated), and a required positional cannot follow an optional one, which would take the only word. `-h` asks for help only as a whole word: `-xh` expands to `-x` and `-h`. Every definition is checked in `createCli`, so a broken hint fails at startup. The usage text goes through the multi-line sanitizer like tool text.
- **CLI stdin is strict UTF-8** (`TextDecoder` with `fatal`) and feeds one argument per call: a lenient decode turns invalid bytes into U+FFFD and a hash or encoding tool would answer for different input without an error.
- **`default` and `fallback`**: an empty line runs `default`, and a first word that names no command or alias goes to `fallback` as its first argument. A leading option such as `--help` stays at the root, and a lone `-` goes to the fallback as its stdin word. Every name and alias is known without loading anything, since package commands are definitions; the earlier citty version loaded lazy package commands on every fallback call to read their aliases.
- **CLI output**: the text follows the multi-line policy (quality, anti-recidivism pattern 9): CR and CRLF become LF, escape sequences go, C0/C1 but tab and LF and the bidi marks (U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+206F) are removed, U+2028 and U+2029 become a space, ZWJ and ZWNJ stay; `--json` (tool commands only; `mcp` has no details and rejects it) prints `details` with DEL, C1, the bidi marks and U+2028/U+2029 escaped as `\uXXXX`, so the parsed details stay the same; a returned `isError` goes to stderr with exit code 1. `json`, `help` and `version` are reserved flags. `EPIPE` as in hashes: a closed pipe ends the process with the exit code the command set.
- Terminal and error text go through `sanitizeLine`: `stripVTControlCharacters` first (the family convention), then `Cc`, `Cf`, `Zl`, `Zp` to spaces.
- **Escapes strip in linear time** (`src/escapes.ts`, #10): Node's pattern runs from every unclosed `ESC ]` to the end of the text, so `"\u001B]".repeat(32_000)` took 1 s in `sanitizeLine` and in `stripVTControlCharacters` alike. `stripEscapes` keeps the pattern but cuts the text after the last terminator (BEL, `ESC \`, U+009C), where no OSC can close, and runs the tail without the OSC branch; the CLI's `sanitizeText` uses it in place of `node:util`. The test compares it with one `replaceAll` of that pattern on every string of up to five escape pieces, not with `node:util`: Node 24.15 still ships an older pattern (`"\u001B\u0007"` strips to nothing there), so its answer depends on the runtime.

## Stack

Toolchain variant, chosen by Ori (2026-09-30): **obuild + Vite+**. obuild builds (`build.config.ts`, TypeBox bundled into `dist/_chunks/libs/typebox.mjs`); Vite+ 1.0 lints, formats and tests (`vp lint`, `vp fmt`, `vp test`, test API from `vite-plus/test`), configured in one `vite.config.ts` on `@agntn/ox`. `vite` and `vite-plus` come from the pnpm catalog with the `vite` override, as in `_template-vite-plus`; CI installs through `voidzero-dev/setup-vp`. Switching variants did not change `dist` (byte-identical build), and a planted `prefer-readonly-parameter-types` violation proves the type-aware rules run under `vp lint`.

Node.js >= 26, TypeScript (strict), pnpm.
